# 文本确认、逐页配图与 PDF

在制作图文读物时读取。先完成入口规定的需求澄清、写作、级别与语言审校，保留默认美式英语和原有 D 级重复目标。这里只增加制作流程，不更改级别指标。

## 1. 给用户看具体文本，再记录确认

每次作品使用单独的版本目录，例如 `output/raz/<topic>-<level>/v1/`。把已审文本存为 UTF-8 `book.json`，不含图片文件路径，避免添加图片使文本确认失效：

```json
{
  "title": "A Short Original Title",
  "level": "D",
  "dialect": "en-US",
  "topic": "用户主题",
  "pages": [
    {"page": 1, "text": "Exact reviewed English body text."}
  ],
  "questions": [
    {"question": "A reviewed question?", "answer": "A reviewed answer."}
  ]
}
```

这里的单页只说明格式，实际页数、词数和题数遵从已确定任务。题答默认 3 道，用户不要题目时用空数组。换行可以保留，但页号须从 1 连续且正文非空。正文通过正式 `count_reading.py` 计数，不能把题答或标题计入。另存画面计划与 `language-review.json`，后者记录英语变体、审查范围、问题页码/原文/建议/理由和最终结论，并绑定实际所审 `book.json` 的 SHA-256；不能拿旧稿的 PASS 为新稿背书。

在聊天中完整展示本版本的标题、逐页正文、题答、正文词数，以及重要的画面依赖和成品安排。必须等用户对该具体文本的明确确认；若用户修改，先修订和复审，再给出新版本确认。不得把阅读任务的最初授权或用户只说“继续写”当成对后来文本的确认。

```bash
rtk proxy python3 <skill>/scripts/content_gate.py digest <version>/book.json
```

得到正文文件摘要后，**只有收到实际确认才**写 `approval.json`：

```json
{
  "status": "confirmed",
  "book_sha256": "本版本 book.json 文件的实际 SHA-256",
  "user_confirmation": "用户对该版本的实际确认原话"
}
```

该记录绑定文字版本，不会自动取得授权，也不能验证回复的真实性；主 agent 负责忠实记录对话。不要预填确认、用示例引号冒充用户原话，或把验证脚本通过说成用户已确认。

在**第一次图片调用前**执行下列检查；恢复被中断的任务时也先查对应版本。失败则停在文字确认阶段，不生成图片或正式 PDF：

```bash
rtk proxy python3 <skill>/scripts/content_gate.py check <version>/book.json <version>/approval.json
```

确认以后不重写 `book.json`。正文、标题、题答或分页变化，都需要对新版本重新审校和确认；图片文件路径、提示词与技术日志另存。

## 2. 一页一图，保持跨页一致

- 制作前读取可用的 `imagegen` 技能，默认使用内置图片生成工具。发现工具不可用时报告缺项；不擅自转到需密钥的 API/CLI。当前环境中可通过工具发现定位 `image_gen`；调用以实际工具 schema 为准，不臆造输出路径或参数。
- 按已确认的画面计划维护一小段角色与场景设定：人物外貌、衣着、关键道具、相对位置、色彩和媒介。不添加影响理解的新情节。故事使用原创儿童插画；说明文依主题采用清晰插画、科学示意图或已约定的照片风格。
- **每个正文页单独生成一张图**，按 `page-01.png` 等保存。提示词包括该页正文、要画的事实/动作、必须保留的角色设定、前后页承接、竖版或近方形构图。画面内不要生成整页英文正文、页码或 Logo；这些由 PDF 排版，以免拼字失真。
- 有效的跨页角色参考可使用已经生成的前页图或角色图。引用本地图像前先看图，随后使用工具支持的本地参考参数；有参考就明确“保持角色/衣着，只改变本页动作”，不把参考图直接复用为所有页面的成品。不要求额外生成角色设定图，除非确有需要。
- 实际查看每张生成图，检查动作、对象数量、壳与身体关系、影子/光源、物品位置、科学机制以及人物一致性；图中需要表达的正文线索必须可见。对确有问题的图，每页最多 2 次有针对性的修订，仍不合格就记录缺项，不交付伪成品。
- 将工具返回的实际选定文件复制到本次作品目录，不能仅依赖工具缓存路径。保留逐页提示词与必要的引用说明；不通过 Python/SVG 占位来替代用户要求的生成插画。技术排版测试素材应明确标注为测试，不能进入正式读物。

图片完成后，创建 `images.json`。它也绑定已确认的文字摘要，路径相对该文件：

```json
{
  "book_sha256": "book.json 文件的实际 SHA-256",
  "pages": [
    {"page": 1, "path": "images/page-01.png"}
  ]
}
```

所有正文页都需独立图片，不接受缺页或把一张图反复填充。图片内容和该页语义的对应仍须实际看图，文件哈希不能代替视觉评审。

## 3. 模仿读物的图文组织，生成 PDF

读取可用 PDF 技能，通过 `load_workspace_dependencies` 定位 ReportLab、Pillow、Poppler 等实际依赖并遵从其制作前置要求。采用本地原书中可观察的原则：一页一个清楚场景或概念、上方大图、下方简短文字、白底留白、适合初读的大字号和简洁页码。使用原创版面，不套用官方封面、Logo、版权页或认证文字。

默认学生 PDF 仅含正文页，每页一张大图；理解题与答案另存 `questions.md`。小工具采用半 Letter 竖版（5.5 × 8.5 英寸）。用户指定 A4、封面或题答附页时按其要求另做相应版面，不能默默忽略；复用已确认文本、检查所有新增页面，正文页的大图约定保持不变。

```bash
rtk proxy <python-with-reportlab> <skill>/scripts/build_reader_pdf.py \
  <version>/book.json <version>/images.json \
  --approval <version>/approval.json --output <version>/reader.pdf
```

工具检查确认与图页映射，等比放置图片，单独排可选择的英文文字，并保存 `.layout.json`。缺图、文本改变、文字溢出或过长单词时应失败，不靠截句、极小字号或偷偷增加正文页数补救。优先调整图文空间和合法换行；需要改变文字/分页时回到文本复审确认。

## 4. 渲染并核对实际成品

使用 `pdftoppm` 将 **每一页** 渲染为 PNG，逐页查看，不只检查封面或抽样。主 agent 与评审角色核对：

- 每正文页确有一张对应大图，人物和事实与文本一致；图片无变形，重要对象没有被裁掉。
- 标题、正文、引号、标点、页码可读，没有乱码、溢出、遮挡、漏行或不合适的词中断行。
- 用 `pypdf` 或 `pdftotext` 回读每页正文，与已确认文本逐页比对（只忽略排版换行/空白，不忽略单词和标点），确认页数和顺序；同时校验文字摘要仍与 `approval.json` 一致。

版式和图像可修正后重新渲染，不改用户确认的文字。出现必须改文本的问题时明确退回新版本确认。排版最多 3 次修正仍有实质问题，说明缺项，不声称完成。

最终交付可打开的 PDF、逐页实际图片、可编辑 `book.json` 和单独题答，附简短自然度审校结论与尚存限制。写清实际完成了哪些图片/视觉检查；AI 的语言审校不等于真实母语编辑认证。
